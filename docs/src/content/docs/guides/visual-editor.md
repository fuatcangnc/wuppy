The visual editor builds an entry's body on a canvas instead of typing Markdown. Open a collection, pick an entry and
choose **Edit with Visual**. It edits the same entry as the classic editor and saves through the same API, so
permissions, [MDX rules](/guides/mdx/), [plugin before-hooks](/plugins/hooks/), edit locks and **History** work the
same way.

The editor is adapted from [Instatic](https://github.com/corebunch/instatic) (MIT): the same page tree, editing
actions, component/layout model, panels and drop rules, built on Wuppy's file-based MDX content and Git saves.

## The screen

- **Toolbar:** quick add **Container / Text / Image**, the white **Add** grid opens **Add to canvas**, **Code** opens the
  full code workspace, search layers and commands (Ctrl/⌘+K), undo/redo, editor settings, open the live page, switch
  to the classic editor and save.
- **Explorer** (left rail): **Layers** has a search field and an insert button, coloured HTML-tag pills, module
  icons and expand/collapse chevrons; drag rows to move (top: before, bottom: after, middle of a container: inside),
  double-click to rename, and right-click for an icon menu with duplicate, componentize, copy/cut/paste, wrap,
  insert-module, lock and delete actions. Dragging shows the Instatic-style floating row, a cyan before/after line,
  and an inside highlight that covers almost the whole div/container row (with auto-expand). **Site** groups pages,
  templates (saved layouts) and components in Instatic-style sections with counts and empty states. **Code** edits
  the site stylesheet and the current MDX source. **Media** has search, All/Images/Videos filters, list/grid views,
  image/video thumbnails and upload actions.
- **Code view:** a full-width Instatic-style workspace with a searchable file tree (`src/pages`, `src/styles`,
  `src/components`, `.wuppy/data`), breakpoint/zoom preview toolbar, line-numbered syntax editor, tabs,
  **Saved/Unsaved** status, Ctrl/⌘+S save, and a bottom **Styles/Computed** inspector. Page source and site CSS are
  editable; component/visual JSON files are read-only. Saves use the same Git-backed content and visual-data APIs.
  Single-line authored HTML is parsed into visual nodes, and valid Tailwind utilities are compiled on save (the
  starter includes `@source` for content). The preview refreshes after save; unsaved or invalid classes (for example
  `text-red-10` instead of `text-red-500`) cannot be generated by Tailwind. When an installed GitHub theme is
  active, admins also see its source under `theme: owner/repo`, including `.astro` pages and components; theme source
  files are editable, but a theme rebuild/restart is needed for Astro code changes to reach the running site.
- **Framework** (left rail): colour tokens with shades/tints/transparency, fluid type and space scales, font stacks and
  stylesheet links. **Overview**, **Colors**, **Type** and **Space** tabs.
- **Selectors** (left rail): shared class/element selector library; open a selector to style every element that
  matches across pages.
- **Canvas** (middle): the page in iframes. Click to select, double-click text to edit it in place (Enter commits,
  Escape reverts), drag to reorder, right-click for copy/cut/paste, duplicate, wrap, hide, lock, save as layout,
  componentize, detach or delete. Switch **Design/Live** views and choose the breakpoint/condition in the floating
  context selector.
- **Properties** (right): class pills (click one to edit its selector), the responsive/state context, block fields,
  component parameters and grouped styles (Layout, Position, Spacing, Size, Typography, Background, Border, Effects).
  Token datalists suggest `--v-*` framework values. **Componentize** turns the selected subtree into a reusable
  component.

| Block | Writes |
| --- | --- |
| Container, Columns, Stack, Row, Card, Hero | semantic containers holding other blocks |
| Heading, Text, Quote, Code | `<h1>`–`<h6>`, `<p>`, `<blockquote>`, `<pre>` |
| Button, Link | `<a>` |
| Image, Video | `<img>` (upload from Properties), `<video controls>` |
| List, Divider, Spacer | `<ul>`/`<ol>`, `<hr>`, empty container |
| Component | an instance of a Visual Component, with its own slot content |
| Markdown | free Markdown/MDX text, kept exactly as written |

Keyboard: **Ctrl/⌘+Z** undo, **Ctrl/⌘+Shift+Z** or **Ctrl/⌘+Y** redo, **Ctrl/⌘+D** duplicate, **Delete** remove,
**Ctrl/⌘+C/X/V** copy/cut/paste, **Ctrl/⌘+S** save, **Ctrl/⌘+0** reset zoom, **Ctrl/⌘++/−** zoom, **Shift+1** fit,
**Alt+↑/↓** nudge, **A** open the inserter, **Escape** leave selector/deselect. Undo keeps 100 steps; typing in one
field counts as one step.

### Add to canvas

The Add dialog follows Instatic: a left rail for **Modules / Layouts / Components / Recent** with live counts and a
preview of the highlighted item, and a right pane with search, list/grid toggles, wireframe thumbnails, favourites and
recents. Modules are grouped by category colour; saved layouts and visual components appear as their own sections.
Paste HTML remains available from the left rail.

## What is saved

Each top-level block is saved as one line of HTML in the body, marked with `data-ve="…"`, for example:

```html
<section data-ve="container" style="padding: 32px 16px"><h2 data-ve="heading">Welcome</h2></section>
```

- The same line is valid in `.mdx` and `.md` entries, so existing Markdown pages can be edited visually too.
- Anything the visual editor did not write (your Markdown, components, code blocks) becomes one **Markdown** block and
  is saved back unchanged.
- Text is stored as character references, so `*`, `{`, `<` and the like appear exactly as typed and never become
  Markdown/JSX.
- Inline styles are filtered (no `;`/`{}`/`<>`/quotes/backslashes, `expression()`, `javascript:`; `url()` only https
  or site paths). Responsive and state overrides travel in `data-ve-r`; the public site turns them into CSS.
- Hidden blocks are saved with `hidden`, so they stay in the body but do not show.
- Site-wide framework, selector, component and layout data is saved to `.wuppy/data/visual.json`; public pages get it
  from `/api/public/visual.css` plus per-page generated CSS. Saving is a Git commit like other content.

## Components and layouts

- **Create component** from a layer's context menu or the Properties button. Instances render the component markup
  with their own slot content; **Edit component** changes all instances, and **Update pages** in Explorer → Site writes
  the current component markup into every page that uses it.
- **Save as layout** stores the selected subtree with its styles; insert it later from Add → Layouts or drag it in.

## Limits

- Forms, arbitrary scripts, dynamic loops/bindings, Yjs co-editing and an npm dependency panel are not part of this
  editor: Wuppy validates MDX and stores plain files, so those need a separate security model.
- A Markdown block stays at the top level of the page (it cannot go inside a container).
- Editing saved lines by hand is fine as long as each visual block stays on one line.
- The canvas uses the site's stylesheet and fonts, but Astro-specific components are shown as placeholders.
